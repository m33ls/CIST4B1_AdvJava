## Algorithmic Runtime Complexity
 * A measure of efficiency
    * Cost
    * Time <-
    * Space <-

 * Constant Time Operations O(1)
    * Constant time operations are those that, for a given processor, take the same amount of time regardless of the input size
        * e.g. Addition, subtraction, multiplication, division, and comparisons of fixed size variables
        * Assignment of a pointer
        * Array read / write

 * Growth of Functions and Complexity
    * As the size of input data increases, the behaviour of algorithms changes
    * We often use the term "complexity" to describe how an algorithm's runtime or memory usage changes as a function of the input size

 * Big O Notation
    * This notation provides a standardised way to describe the upper bound of worst-case runtime complexity of an algorithm
        * We care about worst-case scenarios more than best case
    * Goal is to see how functions will scale with size
    * Allows us to analyse algorithms independent of the hardware or implementation

* Common Big O Complexities
Idealised, not exact real word numbers, but reasonable and useful models
As n approaches infinity, the output approaches the model
    * O(1) - Constant Time Complexity
        * Doesn't change with input size
        * Hash Tables *
    * O(log n) - Logarithmic Time Complexity
        * As the input size increases, the algorithm's runtime grows, but at a diminishing rate. Binary search is an example of an O(log n) algorithm.
    * O(n) - Linear Time complexity
        * The algorithm's runtime increases linearly with input size.
* Less efficient
    * O(n log n) - Linearithmic Time Complexity
        * Merge Sort, Quick Sort, intermediate growth between linear and log
    * O(n^2) Polynomial
        * Nested loops
    * O(2^n), O(n!) Exponential and Factorial Time Complexity
        * Recursive algorithms with poor base cases
