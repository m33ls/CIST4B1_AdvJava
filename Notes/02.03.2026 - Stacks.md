# Stacks
* Stack data structure:
    * Retrieves data in reverse order of how stored
    * LIFO - last in / first-out
    * Think of like "hole in ground"
* Stacks used for many tasks
    * Track function calls
    * Memory management
    * Algorithms
* Our use:
    * Use linked lists to implement Stacks
* Adding datta item to stack -> push
* Removing -> pop
    * Remove & return
* IsEmpty()
    * Return true if stack has no elements
* IsFull() - Array Stacks
    * Return true if at capacity, assuming one exists
* Peek()
    * Return top without popping

## Linked List Stacks
* Differences from Array Stacks
    * Dynamic Size: No resize operations
    * Memory utilisation is more efficient
        * No extra allocation
* Always inserting at head, no need for insertAfter or insertAtEnd
* No search or complex remove, popping only removes head
* Overhead: A node by definition will take up more space (Storing data, constructor, and next addr)

## Queue Applications

# Priority Queues
* Queue that stores data based on insertion order, and based on priority
    * Unlike queues, breaks up FIFO ordering
    * Data has priority and queue retrieves higher priority elements first regardless of order
* Elements of a PQ Node
    * Data
    * Link
    * Priority
* When elemented eq'd or dq'd they are positioned based on priority and order second

## Two Brute Force Options
* Sort by priority during insertion
    * EQ becomes $O(n)$
    * Arrays are even worse due to shifting of elements
    * Dequeue and peek manage $O(1)$
* Sort by priority during retrieval
    * EQ becomes $O(1)$ since we just add to the end
    * Retrieval in DQ and Peek become $O(n)$
    * Can use arrays or linked lists

## The Basis of Heaps
* Heaps are an ADT based on Trees
* Specifically: Complete Binary Trees
    * Complete - all the levels of the tree are filled completely exept the lowest level nodes which are filled from as left as possible
* Tree is subject to additional rules which define Heap
    * Much lie how stacks or queues are based on lists with added constraints

## Types of Heaps
* Two types of heaps exist based on parent relationship to their child nodes
* Max Heap
    * Every parent is greater than or equal to its children
    * Largest element on top
* Min Heap
    * Every parent is less than or equal to its children
    * Smalled element on top

## Heap Approach
* Consider properties of a heap, root contains highest value or lowest value depending on heap type
* If we heapify a priority queue by priority, we store the data efficiently only needing to account for heapification
    * EQ: $O(log n)$
    * DQ: $O(log n)$
    * Peek: $O(1)$

## Representing Heaps with Arrays
* Complete trees are difficult to insert into
* So, represent Heaps as an array internally
* For parent node at index 'p'
    * Left child is located at index '2 * p + 1'
    * Right child is located at index '2 * p + 2'
    * Root located at index 0
