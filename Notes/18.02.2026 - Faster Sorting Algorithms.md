# Quicksort
* Quicksort is a sorting algorithm that repeatedly partitions the input into low and high parts ( each part unsorted), and then recursively sots each of those parts.
* Pivot is chosen to divide data into parts lower than it or high than it 
    * Can be any value, typically middle or last element is used 
* Eventually, all elements of the array have been divided into ordered parts

## In-Place Quicksort
* In place algorithms don't require the allocation of additional memory

## Partition Pseudocode
* Make last element pivot, and index boundaries
* Keep track of divide pointer 'i', start one below low bound
* Loop through from low to high bound
    * If current element is less or equal to pivot, increment i and swap arr[i] with arr[current]
    * At end of loop i will be n pivot's spot, swap it into place
    * Return pivot location so it can be excluded in recursive calls
* $O(nlogn)$

* Quicksort is naturally recursive, break it down into base and recursive cases
    * Base case: array of size 1, 0
    * Recursive case: Sort low, sort high
* Similar to binary search

## Efficiency
* Average case: Linearithmic $O(n log n)$
* Worst case: Quadratic $O(n^2)$
* Worst case occurs when worst pivot is always selected, leading to all elements being in one partition
* Usually better than quadratic time complexity, one of the fastest sorting algorithms available

# Merge Sort
## Guaranteed Divide and Conquer
* Random selection of pivot in quick sort means we aren't always being super efficient with our divisions
    * Ideally we divide equally each partition
* In quicksort, we sort then split
* What if instead we split then sort?

## Merge Sort
* Conceptually simple, split an array in two until you are down to one element arrays, then merge them back up one pair at a time in sorted order
* Always split down the middle
    * Guarantees efficiency
* Guarantees best divide and conquer, but we need extra memory space

## Efficiency
* Worst case and average case of $O(n log n)$
* For runtime complexity, one of the most efficient
* However, space complexity becomes a problem
